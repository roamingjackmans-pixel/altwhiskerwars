# 🐱 Alt Whisker Wars

A variant of [Whisker Wars](https://github.com/roamingjackmans-pixel/whiskerwars): the same maps, buildings and
cat-sending battles, with four big changes:

1. **Hidden armies.** Nobody can see how many cats are inside a rival's buildings, the computer included (they show
   **?**). Only two heroes have a skill that looks inside: Doctor Whirl's **Spy Eye** (every building in an area) and
   Morrow's **Food Poisoning** (the poisoned building). Everyone else estimates from what they saw.
   The computer can't see where your squads are going either: it watches which way they walk and rules out buildings
   as the road splits, so an attack around a corner keeps it guessing until you turn. While it can't tell, it waits
   (holding some cats back) or guesses, and easier levels guess more often and get it wrong. Its own Mind Reader shows
   it the truth, the same as it does for you.
2. **New heroes with levelled skills.** 24 heroes, each with exactly 4 skills and no passive. A skill's slot sets its
   catnip cost (20 / 40 / 60 / 80) and cooldown; every skill has 5 levels bought with 🐟 fish (300 / 750 / 1,500 /
   3,000) that shorten the cooldown and strengthen the effect.
3. **Purr Power is army morale and it matters a lot.** 0-5 stars from purr points (500 / 1,000 / 2,000 / 4,000 /
   8,000). Each star: **+25% defense, +5% attack, +10% speed** for every cat you own. Earned by captures (rival
   buildings most), upgrades and knocking out attackers (+10 each); lost by losing buildings, losing cats while
   attacking (−10 each) and sitting still (the drain starts sooner and runs faster at high stars).
   Cats lost attacking refill catnip, up to 5× more when your purr is low, so the side that's behind gets more skills.
4. **Scarce catnip.** Everyone starts with 0 catnip and it refills 30% slower than in Whisker Wars (0.805/s). Catnip
   Gardens keep their original catnip-per-second, so each garden is worth much more.

The look is a back-alley punk zine: near-black paper, hot magenta and acid green, stencil and marker lettering, cats
in eyeliner and studded collars, and a shop full of increasingly strange furs and hats.

Plus an **interactive tutorial**: a real battle with a coach card that walks you through sending cats, attacking,
upgrading, switching buildings (towers up front, forges and gardens at the back), hidden armies, hero skills and
how Purr Power is earned and lost. +600 🐟 the first time you finish it.

**Play:** https://josephjackman.com/altwhiskerwars/

Saves, room codes, friend codes and the update check are all separate from Whisker Wars, so both games can live on the
same site without touching each other.

## Play locally

```bash
npm install
npm start
```

Open http://localhost:8080. To test online play by yourself, open a second browser window
(or an incognito window), create a room in one and join it from the other.

## How online play works

The person who creates the room is the **host**: their browser runs the game simulation and streams
it to the guest 10×/second. Moves travel through one of two connections, chosen automatically:

1. **Game server mode** (most reliable): when the site is served by `server/index.js`, players connect
   through its WebSocket relay at `/ws`.
2. **Peer-to-peer mode** (zero setup): when the files sit on a plain static host, browsers connect
   directly using WebRTC. Matchmaking uses the free public PeerJS service, with its TURN relay as fallback.

Joining tries the server first, then peer-to-peer, so both kinds of rooms work from the same page.

A room holds up to 4 players: the host runs the battle and streams it to up to 3 guests.

Friends (online status and invites) always go peer-to-peer: once a player has opened Battle a Friend (or has friends)
they keep a small PeerJS "presence" peer open while the game is open, and an invite is a short message carrying the room code.
Friend requests use the backup relay's public message servers as a mailbox: a request is a retained message for the other
player's friend code, which the servers keep until that player next opens the game (and the sender's game puts it back each
time they play, until it's answered).

## Deploying

### Option A — any static website (easiest)
Upload the contents of `public/` to any web host (GitHub Pages, Netlify, Cloudflare Pages, your own site,
or a sub-folder of one). It runs in peer-to-peer mode. Done.

This repo already does this: `.github/workflows/pages.yml` publishes `public/` to GitHub Pages on every
push to `main`. The site appears under the account's custom domain at `/altwhiskerwars/` because the repo
is named `altwhiskerwars`.
Each deploy stamps the version shown on the home screen, e.g. `v1.3.42 · 1a2b3c4`: major.minor come from
`package.json`, the last number counts commits, and the 7 characters are the commit.

### Option B — Node server (most reliable online play)
Deploy this whole folder to any Node host that supports WebSockets (Render, Railway, Fly.io, a VPS):

- Build command: `npm install`
- Start command: `npm start`
- Port: taken from the `PORT` environment variable (default 8080)

A `render.yaml` is included for one-click Render deploys.

### Option C — files on your website, server elsewhere
Put `public/` on your website and run the server on a Node host, then edit `public/config.js`:

```js
window.WW_CONFIG = { server: 'wss://your-server.onrender.com/ws', peerPrefix: 'altwhiskerwars-v1-' };
```

## Tools

```bash
node tools/simtest.mjs 40     # AI-vs-AI crash test on all maps
node tools/maptest.mjs        # every map: clear ground under buildings, every road walkable, fair to both sides
node tools/maptest.mjs ridge  # ...and draws the named map(s) as text
node tools/balance.mjs        # round-robin hero win rates (both sides Hard AI)
node tools/probe.mjs whirl    # one hero vs everyone (add a spell id to disable it)
node tools/skilltest.mjs      # casts every hero's every skill in a live battle
node tools/relaytest.mjs      # tests the WebSocket relay with a host and 3 guests (server must be running)
node tools/rejointest.mjs     # tests reconnecting into a room (server must be running)
node tools/lobbytest.mjs      # tests the 2-4 player lobby/match message protocol in memory
node tools/seats.mjs          # 3-4 player maps: road length between bases, strays each seat reaches first, how close seats touch
node tools/seatsim.mjs tripass 900  # does a map favour a seat? same hero and AI on every seat, many games
```

Add `?p2p` to the page URL to force peer-to-peer mode even when the server is available.
`public/dev/art-test.html` and `public/dev/audio-test.html` are preview pages for the art and sound,
and `public/dev/maps.html` shows every map's real background (also stood up the way phones see it).

## Project layout

```
public/            the game (deploy this folder for static hosting)
  index.html, config.js, css/style.css
  shared/          data.js (heroes, skills, Purr Power, buildings, maps), game.js (simulation), ai.js, nav.js (terrain + roads)
  js/              main, ui (menus), match (game loop/input), tutorial, render, hud, art, audio, net, online, profile
  vendor/          peerjs.min.js
server/index.js    static file server + WebSocket room relay
tools/             headless tests
```

Progress (coins, unlocks, skill levels, stats) is saved in each player's browser (localStorage, key `altwhiskerwars.profile.v1`).
